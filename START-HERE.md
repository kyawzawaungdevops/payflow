# Start here

You have the full PayFlow Wallet project—a production-shaped fintech system meant for **hands-on** DevOps learning, not a single-page demo.

## The three files that matter first

1. **This file (`START-HERE.md`)** — read once, then close it.  
2. **[`LEARNING-PATH.md`](LEARNING-PATH.md)** — your week-by-week curriculum. Open it next and start at **Day 0** (prerequisites).  
3. **[`TROUBLESHOOTING.md`](TROUBLESHOOTING.md)** — open when something breaks, not before.

## What everything else is

- **`README.md`** — orientation at the top, architecture diagram, **Environment 1–3** golden paths (MicroK8s, Compose, AWS EKS).  
- **`docs/README.md`** — index so you open **one** deploy guide at a time (especially Week 4 AWS).  
- **`docs/`** — depth (ingress, monitoring, deploy order). **`LEARNING-PATH.md`** links into it at the right week—do not browse all of `docs/` on Day 0.

**Optional long read:** [`docs/INFRASTRUCTURE-ARTICLE.md`](docs/INFRASTRUCTURE-ARTICLE.md) — prose narrative; end of Week 3 or Week 4, not Week 1. Keep private drafts (e.g. scratch notes) **outside** the repo root; merge anything learner-facing into `docs/` when it is ready.

**Field guide (external):** [*Building PayFlow*](https://osomudeya.gumroad.com/l/payflow) complements this repo; **this repo + `LEARNING-PATH.md` win** when anything disagrees.

## AI and your career

What AI still cannot do is debug a broken cluster with **partial logs** and a **real user** waiting. That judgment is what this project trains.

Open [`LEARNING-PATH.md`](LEARNING-PATH.md). Finish **Day 0**. Everything else can wait.
